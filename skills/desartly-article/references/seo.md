# Reader-first SEO

Define the reader’s question and intent before choosing headings. Use a primary phrase and a few natural related terms in the chosen language. If live keyword or Search Console data exists and is authorized, use it for demand and duplication decisions; otherwise label topic selection as editorial judgment, not validated volume. No paid tools or full audit is required to write one article.

When search research is available, make a bounded search in the target language, inspect a small representative set of results and verify the primary sources needed for claims. Identify a specific gap this article can answer. Do not imitate competitors’ prose or claim to have checked inaccessible pages. Current and technical claims need authoritative sources; benchmark opinions remain interpretations.

Use a clear unique title and one H1 supplied by the article template. Native section headings supply H2/H3 only where the CMS supports them. Include the main concept naturally in title, opening and relevant heading; no keyword-density target or stuffing. An excerpt should explain the question and payoff. Suggested search titles around 50–60 characters and descriptions around 140–160 are rough editing guides, not hard Google rules or ranking guarantees; Persian rendering varies. Verify how supported metadata is actually rendered.

Choose a concise stable slug, preserving an existing published slug. Link internally only to real relevant articles/projects, with descriptive anchor text; never invent URLs or insert self-promotional links everywhere. Alt describes the image, not a keyword list. Sources should directly support the claim. Add tables, diagrams or examples only when they clarify the argument. FAQs are optional when real reader questions justify them.

Do not promise rich results, rankings or traffic. Article structured data, canonical/hreflang, indexing, redirects and frontend metadata changes are website work: report verified gaps as separate tasks, not part of an article API save. Do not create duplicate language versions or canonical assumptions without a request and verified CMS support.

For Google’s official content-quality baseline and statistical-evidence rules, read [research-quality.md](research-quality.md). Evaluate actual intent satisfaction and original analysis, not keyword frequency or a made-up SEO score.
